## 1. Objective
Record exact package proof and mark submitted only through the approved evidence gate.
## 2. Business Context
Bidora must retain accountable external submission history without falsely claiming it sent or delivered the bid.
## 3. Scope
Proof registration, human confirmation, mark-submitted, history and correction references.
## 4. Out of Scope
External portal automation, sealed receipts, evidence-free bypass without approved exception design.
## 5. Technical Requirements
Same bid/package/candidate linkage; clean proof version; reported_submitted_at separated from server recorded_at; current capability; scoped idempotency and permanent transition uniqueness; immutable audit and confirmed facts.
## 6. Proposed Implementation Approach
Implement evidence aggregate and confirmation policy; transactionally link proof and append transition/audit/outbox; expose safe history; handle lost HTTP response through same operation key.
## 7. Dependencies
[Approved package](../documents/BID-DOC-003.md), [proof contracts](../backend_contracts/BID-API-006.md).
## 8. Acceptance Criteria
- Given foreign-bid package/proof, then registration is denied.
- Given duplicate committed mark-submitted retry, then original result returns with no duplicate transition.
- Given late capture, then historical external time remains distinct and no on-time guarantee is asserted.
## 9. Testing Requirements
Missing/unclean proof, verifier policy, cross-tenant IDs, stale candidate, repeated keys/body mismatch and post-commit disconnect tests.
## 10. Definition of Done
Exact package/proof lineage and audited retry-safe state transition demonstrated.

### Unapproved package-preparation boundary

Migration `00020_proposal_package_manifests.sql` and `POST /v1/tenderpreneur/bids/{bid_id}/proposal/package-preparations` implement preparation evidence only. The command re-renders the exact current immutable proposal into deterministic PDF/DOCX bytes, records only their SHA-256 hashes/sizes plus a time-specific readiness snapshot, and labels every immutable manifest `UNAPPROVED_PREPARATION_ONLY`. It requires response-edit authority, expected proposal/workspace versions and idempotency; it stores no generated bytes and cannot approve, sign, seal, transmit, mark submitted or claim external acceptance. The proof/exception policy required by this ticket remains blocked. Status: **IMPLEMENTED_NOT_VERIFIED**.

### Package history and safe retrieval metadata

Bid readers can now list at most 100 immutable preparation manifests per keyset page and read one manifest by tenant-local bid/manifest identity. Metadata names fixed `BIDORA_PDF_V1` and `BIDORA_DOCX_V1` render profiles and returns only relative existing export routes plus expected SHA-256 values, sizes and content types. Retrieval therefore reuses the exact immutable proposal-version export path and its current authorization checks; no object key, signed URL, ambient host, stored artifact bytes or external-delivery claim is exposed. Status: **IMPLEMENTED_NOT_VERIFIED**.

### Unverified external-action evidence intake

Migration `00021_external_action_evidence.sql` and `/v1/tenderpreneur/bids/{bid_id}/submission-evidence-reports` add immutable human-reported external-action evidence. A current `tenderpreneur.submission.report` actor must link an exact preparation manifest, preserve an RFC3339 reported action text/instant, name the external system, provide a note, expected workspace version and idempotency. Every record is fixed to `EXTERNAL_ACTION_REPORTED` / `REPORTED_UNVERIFIED`; optional corrections append and uniquely supersede an earlier same-bid report. Audit/outbox facts exclude external reference, note and system name. Reads are bid-authorized and keyset-bounded. No command changes bid state or claims Bidora transmission, submission, proof acceptance or portal confirmation. The ticket's proof/exception and mark-submitted policy gates remain blocked. Status: **IMPLEMENTED_NOT_VERIFIED**.

### Evidence reconciliation preparation

`GET /v1/tenderpreneur/bids/{bid_id}/submission-evidence-reconciliation` derives at most 100 active correction leaves, bounded correction depth, current-proposal package comparisons and package-readiness-at-preparation facts. It reports deterministic blockers including missing/multiple active reports, stale packages, non-ready package snapshots and truncated lineage. It always returns `proof_policy_configured=false`, `can_mark_submitted=false` and `submitted=false`; it neither selects accepted proof nor resolves discrepancies. The response excludes external system names, references and report notes. Status: **IMPLEMENTED_NOT_VERIFIED**.

### Human-confirmed external submission

The approved pilot proof policy is implemented in source as `IMPLEMENTED_NOT_VERIFIED`. Migration `00023_submission_proof_confirmation.sql` extends private documents with `SUBMISSION_PROOF`, permits only exact PDF uploads up to 25 MiB through ten-minute checksum/size-bound MinIO instructions, and reuses fail-closed ClamAV jobs. Reporters now require `tenderpreneur.submission.report`. `POST /v1/tenderpreneur/bids/{bid_id}/submission-confirmation` requires a current `tenderpreneur.submission.verify` actor distinct from the reporter, a session created within 15 minutes, one active report, exact CLEAN proof, exact applicable approved package, zero readiness/review blockers, expected workspace version and idempotency. Confirmation, immutable evidence, audit/outbox and `BID` to `SUBMITTED` commit atomically. Responses fix `submission_basis=HUMAN_CONFIRMED_EXTERNAL_ACTION` and report Bidora transmission, external acceptance and on-time confirmation as false. No waiver, delegation, correction, withdrawal or replacement is implemented. Current runtime expects Tenderpreneur schema 34 after subsequent additive migrations.
