# Backend module contracts

Sources: [module catalogue](../product/07_MODULE_DEPENDENCIES.md), [domain rules](../product/05_DOMAIN_MODEL_AND_BUSINESS_RULES.md). Decisions [002, 006, 010, 018, 024](27_ARCHITECTURE_DECISIONS.md). Execution: [backend](../implementation/06_BACKEND_IMPLEMENTATION.md), [slices](../implementation/20_VERTICAL_SLICES_ROADMAP.md).

All interfaces below are application ports, not permission to call another module's repository. Transaction notation: C control DB, T active tenant DB in its server-assigned cell, E exchange DB. Each command authorizes current actor/context and emits audit plus outbox atomically in the indicated database. Queries filter records, fields and counts before response. Named events are proposed contracts, not all source-defined event IDs. Under BID-ADR-024, a same-database abstract unit of work may compose transaction-scoped owner adapters, but the use-case owner does not acquire another module's generated repository or SQL ownership.

## Later modules: boundaries and gates

| Module | Ownership, application operations and policies | Transaction/events, failure and tests |
|---|---|---|
| Procurement planning/authoring | Requests, tender versions, criteria; ApproveRequest, ConvertToTender, ValidateTender, Publish; RULE-PREQ and RULE-TEN-010–016 | T approval/publication intent; TenderPublished → E projection; reject invalid criteria/date/approval; test immutable published version and no private projection fields. |
| Publication/clarification | Approved public manifests, addenda, questions; PublishAddendum, PublishAnswer; RULE-PUB/CLR | T authoritative change + outbox; E public projection/inbox; hash reconcile on failure; test private questioner identity and readiness invalidation. |
| Submission exchange/opening | Attempts, envelopes, receipts, release authorizations; AcceptSubmission, Withdraw, Replace, Release | E acceptance; KMS/object external effects; RULE-SUB/OPEN; depends publication/package and ADR-009/010. Test closing boundary, key denial, replay, partial release and tamper. |
| Evaluation/award | Assignments, evidence scores, locks, recommendations, award; Score, LockStage, Moderate, ApproveAward | T + outcome exchange events; RULE-EVAL/AWD; depends release/published criteria. Test independent evaluator visibility, financial-stage gate and unauthorized award. |
| AI/search | Jobs, citations, retrieval and public source projections; RequestExtraction, Disposition, IndexAuthorizedSource | T private jobs; public source store separate; RULE-AI; depends secure documents/authz/quotas. Test prompt injection, denied citations, provider outage and unsupported claims. |

Full commands for later modules require release-specific API/schema extensions and governance approvals; their boundaries here prevent accidental implementation as generic CRUD. Use [traceability](29_REQUIREMENTS_TRACEABILITY.md) to connect owner modules to acceptance evidence.
