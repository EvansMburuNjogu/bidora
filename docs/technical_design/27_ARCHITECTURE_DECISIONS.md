## BID-ADR-007 partial approval evidence — 2026-10-18

The requesting user selected option 1, **email and password**, after being presented with Go-owned Argon2id versus managed OIDC. BID-ADR-007 remains Pending Approval because MFA, broader session administration and deployment-owned trusted-proxy/provider values are still undecided. The authorized implementation boundary initially covered a password-only control schema storing Argon2id PHC strings and typed persistence. The user then approved: Argon2id v19 with 64 MiB, 3 iterations, parallelism 2, 16-byte random salt, 32-byte key; 12–128 valid UTF-8 password bytes without trimming/normalization/composition rules; explicit configuration with no fallback; generic failures with dummy-hash work; verified-email-only login; and rehash after successful login when the profile changes. The user subsequently confirmed strict ASCII dot-atom email parsing, preserved display case, full-address lowercase lookup, no provider alias rewriting and generic denial while unverified. They then approved 32-byte random email-verification tokens, SHA-256 at rest, 30-minute expiry, one active `EMAIL_VERIFY` challenge, resend invalidation, atomic single-use consumption, generic invalid outcomes and no automatic metadata deletion pending retention. The user then approved 32-byte opaque hashed sessions/CSRF values, `__Host-bidora_session` Secure/HttpOnly/SameSite=Lax/Path=/ with no Domain, 30-minute idle/12-hour absolute limits, rotation/revocation, memory-only bootstrap CSRF and validated Origin plus `X-CSRF-Token` on unsafe methods. The user then approved fail-closed login limits: identity 5 failures/15 minutes plus 15-minute deny; network 30/minute and 100/15 minutes plus 15-minute deny; HMAC-SHA-256 privacy scopes, generic denials, unknown/malformed accounting and success clearing only identity failures. The bounded login and registration contracts, atomic Redis limiter integrations and unregistered-to-pilot composition were subsequently implemented, without deployment acceptance. Password recovery was then approved as 32 random bytes, SHA-256 at rest, 30-minute expiry, one active challenge with resend invalidation, atomic single use, existing-password-user eligibility and all-session revocation after reset. Its approved fail-closed Redis limits are identity 3/hour and network 10/hour with a 15-minute denial. Public recovery composition remains conditional on explicit deployment configuration. BID-ADR-023 was subsequently approved for the bounded pilot MFA policy.

## Local development amendment: native PostgreSQL

The user subsequently directed **“for local development, lets not use docker and proceed”**. For the bounded FND-004 foundation, native PostgreSQL replaces the earlier Compose/Colima approach; no QEMU installation is needed. This amends only the local deployment mechanism in BID-ADR-004, not NATS/outbox, Redis, S3, tenant isolation or production topology. System tools report PostgreSQL 15.17 (Homebrew), now known to be within upstream security-advisory affected ranges. The user authorized a separate native 15.19 source installation; its build/version checks passed without replacing system tools. Broader security/runtime acceptance remains separate from this deployment choice. Existing clusters/profiles must not be adopted or deleted implicitly. FND-004 records the new code increment, resource constraints and remaining gates.

## Decision procedure

A decision acceptance records owner, date, requirement references, alternatives, security/privacy consequences, validation evidence and superseded references. Until recorded, dependent tickets are blocked, while unrelated foundation work may proceed only under an authorized implementation task.
